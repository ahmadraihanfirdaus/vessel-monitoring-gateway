## Safety and lifecycle

`run_live_http_integration.py` defaults to a read-only preflight. `--execute`
explicitly permits test fixtures after exact empty-catalog admission. It requires
an explicit PHP executable; actual runtime must be 8.2.35. The approved local
testing file is consumed internally by the existing guarded loader. The ordinary
`.env` is never bootstrapped. Effective target/account/version/grants, all
primary/secondary connection rules, table/migration shape and testing environment
remain enforced. An ephemeral cipher-compatible APP_KEY is process-only.

The test profile uses actual database sessions/cache and Secure/HttpOnly/Lax
cookies, with a random cookie/cache namespace. A quoted `"null"` environment
value selects the literal NullHandler channel; unquoted `null` is parsed by
Laravel as a null configuration value. All mail/queue/telemetry settings remain
controlled testing settings. Fixture freshness policy is explicitly 60/120
seconds for test execution, not a vessel default or performance threshold.

`TestSchema::assertCatalog` extracts existing shape checks. The normal
`assertMigratedAndEmpty` still rejects every populated application table; the
new guard has a regression proving this. A populated HTTP fixture is admitted
only under an additional random lease, exact derived identities, immutable token
digest proof, user marker, session address/agent and literal cache prefix. The
constant C99 device name alone is not proof of ownership. Foreign rows, changed
proof, schema extras or configuration overrides block the operation.

`live_http_fixture.php` is CLI-only. Preparation uses application models/query
builders in the verified empty test catalog. Cleanup verifies ownership again
inside a transaction, deletes only exact owned records, then requires zero
application rows. There is no migrate:fresh/reset, manual DDL, production seed,
table-wide deletion shortcut or unrelated-data cleanup. A failed prepare or test
still attempts guarded cleanup. An unowned/uncertain cleanup blocks the gate,
retains nonsecret temporary lease context and removes its generated private key.
No broader deletion is attempted.

## Actual request path

An ephemeral CA and leaf certificate are generated by the selected PHP OpenSSL
runtime in a verified owned temporary directory. Root private material stays in
memory; the temporary leaf private key is never logged, staged or installed in
an OS trust store. TLS is bound to loopback, and the client explicitly trusts
only the generated CA for positive cases. Wrong CA/hostname and plaintext input
are tested as negatives. This is a local test deployment, not public TLS.

The TLS proxy has a fixed loopback upstream, exact Host allowlist, bounded body/
reply lengths and no redirect following. It replaces forwarded headers with its
known scheme. The test front controller trusts only that loopback proxy's scheme
header and enforces the random test-client marker. It uses the existing
`TestApplication`, retains APP_ENV=testing and explicitly disables only the
framework's *testing bypass* of CSRF. Actual CSRF enforcement remains active.
It never serves arbitrary source files or uses the ordinary public dotenv entry.

The fixture's six actual core/snapshot-recovered C99 packets cross TLS/TCP/PHP
and real Laravel/MySQL services. API checks include dedup/conflict, null/quality,
pagination, authentication, identity, MIME and 4,096/4,097-byte boundaries.
Additional synthetic HTTP event facts test ACK/CLEAR distinction and replay;
these event facts are not claimed as additional native firmware output.

The browser-style client uses a real cookie jar and submits actual CSRF forms.
Session rotation is proven by readonly fingerprints of database session IDs,
not by comparing randomized encrypted cookie bytes. Those fingerprints, cookies,
form bodies and raw inputs are not copied to evidence. Grant revocation/account
disablement are checked on subsequent requests, then logout destroys the
authenticated session. The separate rate-limit case starts with a cleared
*owned* cache namespace and verifies five failures followed by an actual 429
across fresh PHP requests; no throttle middleware is disabled.

Only the owned child process and sockets are stopped. Temporary recursive
cleanup first rechecks the resolved absolute directory, parent, prefix and
absence of a symlink. Repository evidence and user files are retained. Source
input hashes before/after the run must match before success is reported.
